# 消息采集与配图规则

发现消息的渠道只是入口。生成新卡片前，模型先从已知材料提炼保留产品名和版本号的简短检索词，采集流程查找原文中的外部资料和搜索引擎中的同事件报道，抓取候选正文，再交给模型核对。搜索结果摘要只能提供线索，不能直接当作证据。

模型必须逐项核对主体、产品或模型版本、发布行为和时间；同一公司或同一研究领域不等于同一事件。模型只能选择实际抓取的来源，输出双方共同出现的独特名称和补充正文中的连续原句。程序逐字核对名称和引句，未知、无法访问或无法匹配的来源不加入资料。论文插图核对精确 arXiv 编号、版本和标题，访问 arXiv 时继续遵守原站抓取间隔。

写作模型同时获得原始材料及已匹配的补充正文，列出实际来源链接；不同来源存在冲突时说明分歧，不能拼接成未经证实的新事实。配图由采集程序下载、校验格式和尺寸并保存署名，写作模型不能编造图片地址。新闻合集必须按单条消息找图，不能把整份合集封面、其他条目的图或企业头像当成本条配图。

新卡片自动发布最多两张来源匹配的图片，手工审核仍可调整主图、撤下或添加图片（总数最多四张）。历史论文补扫优先为每篇缺图论文找到一张可用插图，遵守原站抓取间隔，提高整批消息的配图覆盖率；已有图片不撤下。候选图下载失败时继续尝试其余候选；所有图片保留实际图源页面，原始新闻链接仍单独保留。没有可用图时继续如实显示暂无图片。历史卡片的补图不重写正文、不改变日期、审核决定或日报/周报/月报归属。

日常采集结束后，还会对前两天采集且仍无图的消息补查，每轮日常采集最多五条，优先重试已有候选图但未成功下载的消息。同一条消息当天不重复补查，也不立即重试刚生成的消息，给原站内容生成或网络恢复留出时间。

历史补扫先预览范围，再执行：

```bash
ai-daily news-media-enrich --since 2026-10-18 --until 2026-11-18
ai-daily news-media-enrich --since 2026-10-18 --until 2026-11-18 --apply --workers 6
```

每张修改前的原卡备份在 `data/backups/news-media-enrichment/notes/cards/`。再次执行默认跳过已处理版本；`--retry` 可重新查找，`--limit` 可先验证小批量。配图和补充来源与原卡的来源绑定，原链接发生变化时旧记录失效，避免串图。日常部署继续排除云端新闻、图片缓存、备份和私有配置。
